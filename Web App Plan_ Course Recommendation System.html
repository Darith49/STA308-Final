Web App Plan: Course Recommendation System

STA308 Final Project | Companion to the Project Plan | Stack: Python + Streamlit

Assumptions: the model is frozen by end of Week 9, the app is built in Weeks 10-11, and one or two developers work on it. Streamlit is the default; a FastAPI variant is described in Section 4.4.

1. Purpose and Success Criteria

Purpose: give a student (or advisor) an instant, explainable elective recommendation from their core grades, and show graders the evidence behind it.

Criterion Target
Recommendation returned Under 2 seconds after submit
Output per query Top-3 electives, predicted grade, interval, explanation
Input errors handled 100% of invalid inputs give a clear message, never a crash
Evaluation visible Baseline vs model results viewable in-app
Deployment Public URL plus local-run instructions plus backup demo video
Reproducibility Fresh install runs from requirements.txt with one command

2. Users and Requirements

2.1 Personas

  • Student (primary): knows own grades, wants a quick suggestion and a reason to trust it.
  • Advisor (secondary): wants to see all electives ranked, flags for unmet prerequisites, and cluster profile.
  • Grader/lecturer: wants to see method, metrics, limitations, and that the app matches the report.

2.2 User Stories

ID Story Priority
U1 As a student, I enter my core grades and get my top-3 electives Must
U2 I see why each elective was recommended Must
U3 I see my strength profile as a chart Must
U4 I can upload a CSV of grades instead of typing Should
U5 I see the uncertainty of each prediction Must
U6 I see which electives I can't take yet (prerequisites) Should
U7 As an advisor, I see the full ranked list of electives Should
U8 As a grader, I see model comparison and limitations Must
U9 I can download my results as PDF or CSV Could
U10 I can compare two students side by side Could

2.3 Functional Requirements

  • FR1 Accept grades for all core subjects (0-100), allowing some to be left blank.
  • FR2 Validate inputs before calling the model.
  • FR3 Scale inputs with the training scaler, project onto PCA, assign cluster.
  • FR4 Predict grade for every eligible elective with a prediction interval.
  • FR5 Rank by combined score (predicted grade plus similar-student success).
  • FR6 Return explanation: top contributing core subjects per elective.
  • FR7 Display charts: radar profile, ranked bar chart with intervals.
  • FR8 Provide data exploration and model performance pages using precomputed results.
  • FR9 Provide methodology, limitations, and privacy notice.

2.4 Non-Functional Requirements

  • Performance: models load once (cached); predictions under 2 s.
  • Privacy: entered grades are never stored or logged; no login.
  • Usability: works on laptop and phone widths; labels in plain language; color-blind-safe palette.
  • Reliability: graceful error messages; app never shows a Python traceback.
  • Maintainability: logic separated from UI; type hints and docstrings.
  • Reproducibility: pinned dependencies, saved random seeds, model metadata file.

┌───────────────┐    ┌──────────────────┐    ┌────────────────────┐

│ (pages,forms) │    │ schema + ranges  │    │ pure Python funcs  │
└───────────────┘    └──────────────────┘    └─────────┬──────────┘
        ↑                                              │ loads
        │ charts/tables                       ┌────────▼─────────┐
        └─────────────────────────────────────│ models/ artifacts│
                                              │ scaler, PCA, KMeans,
                                              │ regressors, metadata,
                                              │ neighbor matrix, metrics
                                              └──────────────────┘

Rules:

  1. src/recommend.py has no Streamlit imports. It can be tested and reused anywhere.
  2. The app never trains. src/train.py produces artifacts offline.
  3. All numbers shown on Performance/Explore pages come from models/metrics.json and models/eda_summary.json, generated by the notebooks, so the app and report always match.

3.1 Artifact Contract (what train.py must save)

File Contents
scaler.joblib StandardScaler fit on training core grades
pca.joblib Fitted PCA (or factor model)
kmeans.joblib Cluster model and label names map
elective_models/{elective_id}.joblib One regressor per elective
neighbors.joblib Student-by-core matrix (anonymized, standardized) for similarity, plus elective grades matrix
residual_stats.json Per-elective residual SD for prediction intervals
metrics.json RMSE, MAE, R², Precision@3, NDCG@3, coverage for model and baselines
metadata.json Library versions, training date, seed, subject list and order, data source label (real/synthetic)
prereqs.json Elective to required core subject(s) and minimum grade

Order of subjects in metadata.json is the single source of truth for input columns.

3.3 Handling Missing Core Grades

  • If 1-2 grades missing: impute using regression from the other cores (fit at training time) and show a warning banner.
  • If more than 2 missing: refuse and explain that at least N grades are needed.
  • Always list which values were imputed in the results.

3.4 Prediction Interval Method

Use pred ± 1.96 × residual SD from cross-validated residuals, clipped to 0-100. State clearly that this is an approximate 95% interval. (For random forest, use quantile across trees or conformal residuals.)

3.5 Explanation Method

  • Linear/ridge: contribution_i = coefficient_i × z-score_i; show top 3 by absolute value.
  • Random forest: use permutation importance globally plus SHAP for local explanations if time allows.
  • Display in plain language: "Strong Calculus grade (+4.2 points) and Statistics (+3.1) raise your predicted score in Econometrics."

4. Tech Stack

4.1 Libraries

streamlit, pandas, numpy, scikit-learn, statsmodels, joblib, plotly (interactive charts), pydantic (validation), pytest, black, ruff. Optional: shap, reportlab or fpdf2 for PDF export.

4.2 Environment

Python 3.11, virtual environment, requirements.txt with pinned versions, Makefile or run.sh with train, test, app targets.

4.3 State Management

Use st.session_state for the last submitted grades and results so switching pages doesn't erase them. Use @st.cache_resource for model loading and @st.cache_data for static tables and charts.

4.4 Optional FastAPI Variant

Expose POST /recommend (JSON grades in, ranked electives out), GET /metrics, GET /health. Streamlit calls it via requests. Adds architectural depth but costs about a week; only do this if the model is frozen early.

Inputs

  • Number inputs with min 0, max 100, step 0.5, blank allowed, tooltips with subject descriptions.
  • "Use sample student" button that fills three preset profiles (for demo and testing).
  • CSV upload: columns must match subject names; show a template download; validate headers and types; first row used (or a selector for multi-student files).

Validation rules

Rule Message
Value outside 0-100 "Grades must be between 0 and 100."
Non-numeric "Please enter a number for {subject}."
More than 2 blanks "Please enter at least {n} grades so the estimate is reliable."
CSV header mismatch Show expected vs found columns
All grades identical Warning: "Profile may be uninformative"

Outputs

  1. Profile card: cluster name, short description, radar chart comparing student to cluster average and overall average.
  2. Top-3 cards: rank, elective name, predicted grade, interval, category, expandable "Why?" with contribution bars, and a similar-student note ("Among 15 similar students, average grade was 81").
  3. Interval bar chart for all eligible electives.
  4. Expanders: full ranked table, blocked electives with reason ("Requires Calculus ≥ 60"), imputed values list.
  5. Buttons: download CSV (and PDF if built), "Start over".
  6. Persistent disclaimer: "Predictions are estimates from past grades, not guarantees. Consider your interests and consult an advisor."

5.4 Explore Data

Tabs: Distributions (histograms per subject, boxplots), Correlations (heatmap with hover), Profiles (scree plot, PCA loadings table, cluster sizes and mean-grade profiles), Electives (grade distribution per elective, enrolment counts). All read from precomputed files. Add a subject selector and category filters.

5.5 Model Performance

  • Comparison table: baseline mean, student-GPA baseline, linear, ridge/lasso, random forest (RMSE, MAE, R²).
  • Recommendation metrics: Precision@3, Recall@3, NDCG@3, coverage vs popularity baseline.
  • Charts: predicted vs actual scatter, residual plot, feature importance, metric bars with bootstrap CIs.
  • Fairness/stability box: group error gaps, bootstrap overlap.
  • Text summary: "Best model reduces RMSE by X% versus baseline (p = ...)."

5.6 Methodology and Ethics

Data source and size, pipeline diagram, methods summary, assumptions and diagnostics summary, limitations, ethics (privacy, bias, grades vs interest), model version and training date from metadata.json, links to report and repo.

6. UX and Design Guidelines

  • Layout: wide mode, three-column input grid, results below inputs.
  • Palette: one primary color, one accent, neutral grays; use Okabe-Ito colors for categories.
  • Typography: default Streamlit font, clear headings, no walls of text; use expanders for detail.
  • Feedback: spinner during computation, success/warning/error banners with plain-language text.
  • Accessibility: contrast ratio 4.5:1, alt text or captions for charts, no meaning conveyed by color alone.
  • Microcopy: avoid jargon on the main page ("strength profile" not "PCA scores"); jargon lives in Methodology.
  • Trust: always show uncertainty, data source, and a disclaimer.

7. Testing Plan

7.1 Unit Tests (pytest)

Test Expectation
validate_grades with valid input passes
Out-of-range, non-numeric, too many blanks correct error messages
build_profile with training-mean grades z-scores near 0
recommend returns exactly top_n, sorted descending true
Intervals satisfy lo ≤ pred ≤ hi and within 0-100 true
Prerequisite filter blocks ineligible electives true
Determinism: same input gives same output true
Monotonicity: raising a strongly weighted grade never lowers that elective's prediction (linear model) true

7.2 Integration and Regression

  • End-to-end test: sample CSV in, recommendation table out.
  • Golden-file test: 5 fixed student profiles must reproduce saved outputs; if you retrain, update the golden file deliberately.
  • Artifact test: metadata subject order matches the input form.

7.3 Manual and User Testing

  • Test on Chrome and Firefox, laptop and phone width.
  • User test: 5 classmates each complete 3 tasks (get recommendation, find why #1 was chosen, find model accuracy). Record time, errors, and a 1-5 clarity rating, plus one open comment. Summarize for the report (average time, common confusions, changes made).
  • Edge cases: all zeros, all 100s, one blank, three blanks, decimals, huge CSV, wrong headers, rapid repeated clicks.

7.4 Acceptance Checklist

  • All Must stories work end to end
  • No traceback visible under any tested input
  • Numbers in app match report tables exactly
  • Fresh clone runs following README only
  • Deployed URL works from another device

8. Deployment and Operations

  1. Prepare: requirements.txt, runtime.txt (Python version), .streamlit/config.toml (theme, wide layout), small artifacts (keep under repository size limits).
  2. Deploy: Streamlit Community Cloud from GitHub (main branch, app/app.py). Alternative: Hugging Face Spaces.
  3. Never deploy raw student data. Only trained artifacts and aggregate statistics.
  4. Backup plan: record a 2-3 minute demo video; keep a local copy running on your laptop; keep screenshots in the slides.
  5. Release tags: tag v1.0-submission in Git at final submission so the graded version is fixed.
  6. Monitoring: none needed beyond a manual check the day before presenting; wake the app (cloud apps sleep) 10 minutes before the demo.

9. Security and Privacy

  • No database, no logging of grades, no cookies beyond Streamlit defaults.
  • Validate uploads: file size limit, CSV only, ignore extra columns, never eval or execute file content.
  • Pin dependencies and avoid unmaintained packages.
  • State on the About page: "Your grades are processed in memory and not stored."
  • Keep secrets (if any) in Streamlit secrets, never in the repo.
